# Songs Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a ♪ Songs tab to the Korean app. It shows the user's own songs line by line with romanisation, Traditional Chinese, English, grammar points and words, and any of them can be added to FSRS reviews with one tap.

**Architecture:**

- A self-contained `songs/` module:
  - `model.js`: pure logic, tested in Node.
  - `lrclib.js`: lyrics lookup.
  - `claude.js`: the API call through the vendored official SDK.
  - `db.js`: IndexedDB storage.
  - `view.js`: rendering and clicks.
- `app.js` plugs it in the same way it plugs in the quiz (`createQuiz`). The plug-in point is a `songs` factory on the Korean pack.
- Lyrics and translations live only on the phone.

**Tech Stack:**

- Vanilla ES modules, no build step.
- `node:test`.
- Playwright 1.63, already installed globally. Set `PLAYWRIGHT_MODULE=/opt/node22/lib/node_modules/playwright/index.mjs`.
- `@anthropic-ai/sdk` 1.3.0 (already pinned in `package.json`), bundled once with esbuild 0.25.12.

**Spec:** `docs/superpowers/specs/2026-11-03-songs-tab-design.md`

## Global Constraints

- **No real lyrics anywhere in the repo:**
  - Fixtures use only the invented lines in Task 1.
  - The user's song list is never committed.
- **Default model:** `claude-haiku-5-5`. The other options are `claude-sonnet-5-5` and `claude-opus-5-5`, with no date suffixes.
- **Prices in US$ per million tokens (input / output):**

  | Model | Input | Output |
  |---|---|---|
  | Haiku 5.5 | 0.10 | 0.50 |
  | Sonnet 5.5 | 2 | 10 |
  | Opus 5.5 | 4 | 20 |

  Cache read is ×0.1 and cache write ×1.25 of the input price.
- **Fallbacks:** `fallbacks: "default"` with beta `server-side-fallback-2026-07-01` on Sonnet 5.5 and Opus 5.5 only. Never on Haiku.
- **API key:**
  - Stored only under `localStorage["korean.songs.apiKey"]`.
  - Never part of `state`, `exportJSON` or any backup.
- **Escaping:** every string from lyrics, LRCLIB, the model or a backup goes through `esc()` before it reaches `innerHTML`.
- **Other apps unchanged:** Cantonese, Mongolian and English get no tab and no code path changes.
- **Ids:**
  - New study items use the `u${Date.now().toString(36)}` scheme already used by `app.js`.
  - Songs use `s${Date.now().toString(36)}${random 4 chars}`.
- **Copy:** UI text is English, in Australian spelling, matching `ui/en.js`.

## Review Focus

1. **Takeout CSV with BOM, CRLF and quoted commas** (`"Love, Again"`): titles must come through whole. Test in Task 1.
2. **A song with no Hangul** (English or romanised lyrics): "Nothing to translate", with no API call and no charge. Tests in Task 1 (model) and Task 7 (view).
3. **A long song stopped at `max_tokens`, or a reply with missing or shuffled line numbers:** nothing partial is saved, and the song is marked *error* with Retry. Tests in Tasks 2 and 5.
4. **Tapping + Add to study twice, or on a word already in the deck:** no duplicate card; the button shows ✓ In reviews. Test in Task 3.
5. **IndexedDB unavailable** (blocked storage or a private window): the Songs tab shows a message, and the rest of the app works. Test in Task 6.

**Files:**

**Interfaces:**
- Produces, all exported from `songs/model.js`:

### Task 2: Request building, response checking, cost

**Files:**
- Modify: `songs/model.js`
- Test: `test/songs-model.test.js`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `SONG_MODELS: {[id]: {label, in, out}}` (prices as in Global Constraints) and `DEFAULT_MODEL = "claude-haiku-5-5"`.
  - `systemText(grammar: {id, form, en}[]): string`: the `RULES` text below, then `"\n\nGRAMMAR LIST (id | form | meaning)\n"`, then one `id | form | en` line per grammar point.
  - `buildRequest({model, lines, grammar}): object`: the Messages API params, built as follows.
    - `{ model, max_tokens: 64000, system: [{type: "text", text: systemText(grammar), cache_control: {type: "ephemeral"}}], messages: [{role: "user", content: lines.map((l, i) => `${i + 1}. ${l}`).join("\n")}], output_config: {effort: "medium", format: {type: "json_schema", schema: ANALYSIS_SCHEMA}} }`
    - Plus `betas: ["server-side-fallback-2026-07-01"], fallbacks: "default"` when `model !== "claude-haiku-5-5"`.
  - `ANALYSIS_SCHEMA`: `{lines: [{n: integer, zh, en, grammar: [{form, appId: string|null, en, zh, note}], words: [{ko, base, hanja: string|null, zh, en, pos}]}]}`.
    - Every object is `additionalProperties: false` with all keys required.
    - Nullable fields use `anyOf: [{type: "string"}, {type: "null"}]`.
  - `parseAnalysis(text: string, lines: string[], grammarIds: Set<string>): {lines: {ko, zh, en, grammar, words}[]}`.
    - Throws `Error("invalid")` on bad JSON, a wrong shape, or a missing or duplicate `n` (each `n` must cover 1..lines.length).
    - Orders the result by `n` and sets `ko` from `lines[n-1]`.
    - Sets an unknown `appId` to `null`.
    - Cuts every string to 400 characters.
    - Keeps the first 5 words per line.
  - `estimateCost(model, lyricsChars: number, lineCount: number, systemChars = 9000): number` (US$):
    - Input tokens = `Math.ceil(systemChars / 3) + Math.ceil(lyricsChars / 1.5)`.
    - The view passes `systemText(grammar()).length` as `systemChars`.
    - Output tokens = `200 * lineCount + 2000`.
  - `actualCost(model, usage): number` (US$), using `input_tokens`, `output_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens`.
- Copy for `RULES` (exact):

```
You help a Korean learner (TOPIK 3–4, reads Traditional Chinese and English) study song lyrics.
For each numbered line: give a natural Traditional Chinese translation (zh) and a natural English translation (en), not word for word.
grammar: the grammar points in that line worth learning. Skip particles and endings a TOPIK 3 learner already knows unless used unusually. For each give form (e.g. -(으)ㄹ수록), en and zh meanings, and a one-sentence English note on how it works in this line; mention casual or poetic contractions (난 = 나는, 널 = 너를). Set appId only if the line truly uses that point from the GRAMMAR LIST, else null.
words: up to 5 content words: ko as in the line, base = dictionary form, hanja for Sino-Korean words else null, zh, en, pos (n, v, adj, adv, phrase).
Return n = the line number you were given for every line, once each.
```

- [ ] **Step 1: Write the failing tests:**
  - `buildRequest({model: DEFAULT_MODEL, lines: ["가", "나"], grammar: [{id: "g-int-1", form: "-기 위해", en: "in order to"}]})`:
    - `messages[0].content === "1. 가\n2. 나"`
    - `system[0].text` includes `"g-int-1 | -기 위해 | in order to"`
    - `system[0].cache_control.type === "ephemeral"`
    - no `fallbacks` and no `betas`
  - With `"claude-opus-5-5"`: `fallbacks === "default"` and `betas` deep-equals `["server-side-fallback-2026-07-01"]`.
  - `parseAnalysis` on a valid two-line reply with `n` in the order 2, 1 returns the lines in order 1, 2, with `ko` filled in.
  - `parseAnalysis`:
    - Throws `/invalid/` for: a missing `n`; a duplicate `n`; truncated JSON (`'{"lines":[{"n":1'`); `zh` being a number.
    - Turns `appId: "nope"` into `null` and keeps `"g-int-1"`.
    - Cuts a 1,000-character note to 400 characters.
  - Cost:
    - `actualCost("claude-haiku-5-5", {input_tokens: 1e6, output_tokens: 1e6, cache_read_input_tokens: 0, cache_creation_input_tokens: 0})` is `0.6`, within 1e-9.

    - `estimateCost("claude-haiku-5-5", 600, 20)` is between `0.002` and `0.005`.

### Task 3: Study items from a song

**Files:**
- Modify: `songs/model.js`
- Test: `test/songs-model.test.js`

**Interfaces:**
- Consumes: `validateItem` from `lib/validate.js`.
- Produces `studyItem({kind, entry, line, song, items, unit, id}): {id: string, item: object|null}`. It does not schedule anything; the caller does.
  - `kind` is `"grammar"` or `"word"`.
  - `entry` is a G or W from the analysis.
  - `line` is `{ko, zh, en}`.
  - `song` is `{title, artist}`.
  - `items` is all current seed plus custom items.
  - `unit` is `{tier, unit}` for the current unit.
  - `id` is the id to use for a new item.
- How it decides:
  - **Grammar with `appId` matching an item id:** returns `{id: appId, item: null}`.
  - **Grammar without a match:** if an item with the same `form` exists, returns its id. Otherwise returns a new custom grammar item:

    ```
    { id, kind: "grammar", tier, unit, form, en, zh, note: `${entry.note} · ♪ ${title} – ${artist}`, ex: [{ko: line.ko, zh: line.zh, en: line.en}] }
    ```

  - **Word:** if a vocab item with `ko === entry.base` exists, returns its id. Otherwise returns a new custom vocab item:

    ```
    { id, kind: "vocab", tier, unit, ko: base, hanja, zh, en, pos, ex: line.ko, exZh: line.zh, exEn: line.en, note: `♪ ${title} – ${artist}`, check: false }
    ```

  - Every new item must give `validateItem(item, kind === "word" ? "vocab" : "grammar")` → `[]`. If it doesn't, throw `Error("invalid item")`.
- Produces `inReviews(id, progress): boolean`, which is `!!progress[id]`.

- [ ] **Step 1: Write the failing tests:**
  - A new grammar item and a new word item each pass `validateItem`.
  - A grammar entry with `appId` naming a seed id returns that id and `item: null`.
  - **Second tap:** call `studyItem` once, add the new item to `items`, then call it again with the same entry. The second call returns the **first** id and `item: null`.
  - The same applies to words.
  - An empty `zh` in a word entry throws `/invalid item/`.

- `songs/claude.js` exports `translateSong({apiKey, model, lines, grammar}, {loadSdk = () => import("../lib/vendor/anthropic-sdk.js")} = {}): Promise<{analysis, usage, costUsd, model}>`. It:
  1. Creates `new Anthropic({apiKey, dangerouslyAllowBrowser: true, maxRetries: 2})`.
  2. Calls `client.beta.messages.stream(buildRequest(...)).finalMessage()`.
  3. Checks `stop_reason` before reading content: `"refusal"` throws `SongError("refusal")` and `"max_tokens"` throws `SongError("tooLong")`.
  4. Finds the first text block and passes it to `parseAnalysis`. Any parse error throws `SongError("invalid")`.
  5. Maps SDK errors, most specific first:

     | SDK error | `SongError` code |
     |---|---|
     | `Anthropic.AuthenticationError` or `PermissionDeniedError` | `"badKey"` |
     | `RateLimitError` | `"rateLimit"` |
     | `APIConnectionError` | `"offline"` |
     | `APIError` with `status >= 500` | `"server"` |
     | anything else | `"invalid"` |

- Also exports `class SongError extends Error { code }`.

### Task 7: Add, translate, read and study

**Files:**
- Modify: `songs/view.js`, `style.css`
- Test: `scripts/songs-check.mjs`

**Interfaces:**
- Consumes Tasks 1–6.
- **View states:**
  - `list`
  - `add`: a search form with title and artist, results, and a Paste lyrics textarea.
  - `review-lyrics`: title and artist editable, then Save.
  - `song`
  - `import`: a textarea plus a CSV file input `#song-csv`, with checkboxes and a total estimate for a batch.
  - `data-s` values: `add`, `search`, `pick`, `paste`, `save`, `open`, `translate`, `retry`, `line`, `study`, `import`, `importGo`, `batch`, `back`, `delete`, `key-save`, `key-clear`, `model`.
- **Translate:**
  1. With no key, show `Add your Claude API key in Settings` and a button to go to Settings.
  2. With no Hangul lines, show `Nothing to translate: no Korean lines in this song`, with no call.
  3. Otherwise `confirm("Translate with <label>? About US$<estimate>")`, then `translateSong`.
  4. On success, store `analysis` and `status: "done"`.
  5. On a `SongError`, store `status: "error"` and `error: code`. Show the message for that code, and keep the lyrics.
- **Messages by code:**

  | Code | Message |
  |---|---|
  | `badKey` | `The API key was refused. Check it in Settings.` |
  | `offline` | `You're offline. Try again when you're connected.` |
  | `rateLimit` | `Too many requests just now. Wait a minute and retry.` |
  | `server` | `Claude had a server problem. Retry in a moment.` |
  | `refusal` | `The model declined this song. Try Sonnet 5.5 in Settings.` |
  | `tooLong` | `The reply was cut off. Try Sonnet 5.5 for long songs.` |
  | `invalid` | `The reply couldn't be read. Retry.` |

- **Batch:** songs are translated one after another; each failure is stored and the batch continues. Lyrics are fetched first for queued songs, using the first LRCLIB hit that has lyrics. Hits marked instrumental are skipped, because a karaoke or "INST" track title often matches an instrumental entry first.
- **Song page:**
  - A summary showing the model label and `US$x.xxx`, and the grammar points grouped by `appId` or `form` with counts, ✓ when `inReviews`.
  - Each lyric line (blank lines become spacing) is rendered with `say(ko)`, `romanize(ko)`, `zh` and `en` by looking up `normLine(line)` in the analysis.
  - Tapping a line toggles `.open`, showing its grammar and words with `+ Add to study` or `✓ In reviews`.
- **Study:**
  1. `studyItem(...)`. If it returns an item, push it to `state().custom`.
  2. `state().progress[id] = grade(undefined, "good", Date.now())`.
  3. `persist()`, `rebuild()`.
- **Settings HTML:**
